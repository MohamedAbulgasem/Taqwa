Mishary Rashid Alafasy: the four Quranic clips bundled for the first run of the adhkar
Source: Islamic Network per-ayah recitation corpus (https://alquran.cloud, cdn.islamic.network)

Taqwa's Morning & Evening Adhkar (shared/src/commonMain/composeResources/files/adhkar) have four
Quranic items. So that a reader's first session is not silent before anything is downloaded, the
app bundles those four items in the voice of the default reciter, Mishary Rashid Alafasy
(ar.alafasy, 64 kbps), under

    shared/src/commonMain/composeResources/files/adhkar/clips/ar.alafasy/

    002-255.mp3   Al-Baqarah 2:255 (Ayat al-Kursi), one ayah
    112.mp3       Al-Ikhlas, ayahs 1-4
    113.mp3       Al-Falaq, ayahs 1-5
    114.mp3       An-Nas, ayahs 1-6

They play only when Alafasy is the reciter the reader chose and the surah is not downloaded.

What they are. The clips are byte-identical cuts of the corpus's own files, with no re-encoding.
Each clip is made of the ayah MP3s of the passage named in the list above, taken from
Alafasy's `.taqa` container and concatenated in ayah order, the way the app's recitation
previews are cut (the preview for each reciter is the raw bytes of Al-Fatiha 1:1 followed by
1:2). Nothing was decoded, trimmed, re-tagged or re-encoded; every byte of a clip is a byte the
Islamic Network published, at the bitrate they published.

Where the bytes came from. The Islamic Network corpus, as Taqwa mirrors it on the public GitHub
release audio-ar.alafasy-v1 of MohamedAbulgasem/Taqwa-data
(https://github.com/MohamedAbulgasem/Taqwa-data/releases/tag/audio-ar.alafasy-v1), one
`.taqa` container per surah, in which every ayah is the corpus's download byte for byte. The
four containers, each checked against the byte size and SHA-256 that
shared/src/commonMain/composeResources/files/recitation/manifest.json publishes for it
(manifest generated 2026-09-13T15:30:51Z) before anything was cut:

The ranges. Offsets are absolute byte positions in the container, first and last byte
inclusive (a `.taqa` is a 12-byte header, a JSON index, then the MP3s back to back; the index
gives each ayah's offset and length). The corpus's own name for each file is its global ayah
number, https://cdn.islamic.network/quran/audio/64/ar.alafasy/<global ayah>.mp3.

Total 1,063,464 bytes. Cut on 11 October 2026 by tools/quran-audio/adhkar_clips.py; the
clips are a pure function of the four containers, so re-running it on any machine writes the
same bytes, and tools/quran-audio/check_adhkar_clips.py re-derives each clip from the
containers and compares byte for byte (it exits 1 on any difference).

Licence. The terms are the ones docs/ATTRIBUTION.md records for every recitation Taqwa
carries. Its Recitations entry opens with this sentence, quoted verbatim (the Markdown is the
file's own):

    "**Recitations**: per-ayah recordings from the [Islamic Network](https://alquran.cloud) (`cdn.islamic.network`), licensed to them by the reciters or their estates for free, non-commercial redistribution at the bitrates they publish ([terms](https://alquran.cloud/terms-and-conditions), §IV)."

The clips are redistributed on exactly those terms: free, non-commercial redistribution at the
bitrate the Islamic Network publishes, unmodified. Copyright lies with the reciters, and any of
them may ask to be removed. They are not covered by Taqwa's GPL-3.0.
The verbatim text of section IV, as read on 12 September 2026, is quoted in
docs/superpowers/specs/2026-09-12-taqwa-quran-recitation-investigation.md.

Withdrawal. The downloadable catalogue can drop a reciter without an app update; these four
files cannot, because they travel inside the app. If Alafasy, his estate or the Islamic Network
asks for the recitation to be removed, the clips/ar.alafasy folder is deleted from the next
release.
